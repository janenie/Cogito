# 游戏脚本：laboratory_experiment

## 任务定位

`laboratory_experiment` 是一个发生在
`addons/cogito/DemoScenes/COGITO_4_Laboratory.tscn` 的实验推理任务，主要评测玩家或
Agent 是否能够读取部分实验条件、观察设备反馈、排除错误组合，并在最多三次正式实验内
完成一套安全电路。

本文件是开发者玩法说明，不是运行时模型输入。MCP 只能获得单独维护的公开 briefing、
玩家实际看见的任务卡、设备状态和实验结果；不得公开本局答案、材料属性映射、案例编号、
随机种子或未执行组合的结果。

## 核心目标

玩家需要从三块候选电池、三个候选样本和三种处理方式中选出本局唯一正确组合，安装固定
连接件并运行实验，使实验灯在安全条件下稳定点亮 3 秒。

每局最多允许三次完整实验。前两次失败会提供有限的测量结果，供玩家继续推理；第三次仍
未满足成功条件时立即失败。

## 复用现有场景内容

玩法优先复用 Laboratory 的现有物件：

- `Cathode_A`、`Cathode_B`、`Cathode_C` 作为样本 A、B、C。
- 现有 4 块电池中启用 3 块，分别显示为 Alpha、Beta、Gamma。
- 复用现有水飞镖和火飞镖的材质、特效与属性反应，用于表现湿润和加热。
- 现有金属棒和金属棒卡槽作为固定回路连接件。
- 现有电池卡槽用于安装候选电池。
- 现有电灯和通电特效用于显示实验结果。
- 复用 `generic_button.tscn` 制作样本选择、运行实验和复位按钮。

需要新增但不要求新增复杂美术资产：

- 出生点附近的实验任务卡。
- 样本 A、B、C 的可见标签和选择按钮。
- 固定的“保持干燥”“湿润样本”“加热样本”处理按钮。
- Alpha、Beta、Gamma 电池的颜色或文字标签。
- 实验状态面板和最近三次结果面板。
- 管理随机案例、设备状态、尝试次数和终局的实验控制器。
- 复用 `AIPlayController`、executor、interaction probe 和 bridge 的 Laboratory controller
  场景，以及专用 observer 和 terminal monitor。

## 候选池

### 电池

每局启用 Alpha、Beta、Gamma 三块电池。三种性能会随机映射到三个标签，外观标签本身
不直接说明性能。

| 性能 | 基础行为 |
| --- | --- |
| 低功率 | 安全，但可能无法推动高电阻样本 |
| 额定功率 | 适用于多数常规导电组合 |
| 高功率 | 可推动高电阻样本，也可能导致过流或过热 |

电池性能在回合开始后固定。实验运行过程中不再随机改变输出。

### 样本

每局从以下六种材料档案中选择三种，再随机映射到样本 A、B、C：

| 档案 | 干燥 | 湿润 | 加热 |
| --- | --- | --- | --- |
| 湿态导体 | 断路 | 稳定导电 | 断路 |
| 干态导体 | 稳定导电 | 短路 | 导电不稳定 |
| 热激活导体 | 断路 | 电流不稳定 | 稳定导电 |
| 热敏导体 | 稳定导电 | 稳定性下降 | 过热或燃烧 |
| 高电阻导体 | 微弱导电 | 微弱导电 | 电阻降低 |
| 绝缘样本 | 断路 | 断路 | 断路 |

具体电流和温度结果还受电池与环境条件影响。材料档案属于隐藏状态，不能直接显示给
玩家；玩家只能通过任务线索和已经执行的实验结果推理。

### 处理方式

每个正式实验只能选择一种样本状态。正式玩法通过实验台上的三个通用交互按钮选择处理
方式，不要求玩家发射武器，因此可直接使用现有 MCP `interact` 动作：

- `dry`：按下“保持干燥”。
- `wet`：按下“湿润样本”，播放水飞镖命中效果并应用湿润属性。
- `heated`：按下“加热样本”，播放火飞镖命中效果并应用加热或燃烧属性。

同一轮多次选择处理方式时，以最后一次有效选择为当前状态。湿润可以熄灭燃烧效果；复位
会清除湿润、燃烧、通电和临时温度状态。场景中原有飞镖可以保留为普通模式演示物件，
但不是本任务的必需输入，也不参与正确组合判定。

## 实验协议

每局从以下三种协议中选择一种。协议名称、目标和安全限制会公开在任务卡上。

### 稳定导电

目标：选择合适的电池、样本和处理方式，使灯稳定点亮 3 秒。

成功要求：

- 电流位于本局任务卡给出的安全范围。
- 电流稳定性为 `stable`。
- 样本温度不超过安全阈值。
- 样本未短路、未燃烧。

### 防潮测试

目标：验证一个样本在湿润环境中的安全导电能力。

成功要求：

- 当前样本必须处于 `wet` 状态。
- 灯稳定点亮 3 秒。
- 不得出现短路或电流突升。
- 电流和温度位于任务卡范围。

### 耐热测试

目标：验证一个样本经过加热后的导电能力。

成功要求：

- 当前样本必须处于 `heated` 状态。
- 灯稳定点亮 3 秒。
- 样本不能燃烧。
- 最终温度不得超过任务卡阈值。
- 电流位于安全范围。

## 环境条件

每局最多启用一个公开环境修正。修正显示在任务卡和实验状态面板上。

| 环境 | 影响 |
| --- | --- |
| 标准环境 | 不修改基础结果 |
| 高湿环境 | 湿态样本电流提高一级，短路风险增加 |
| 冷却受限 | 加热样本温度提高一级 |
| 电源波动 | 高功率电池的稳定性降低一级 |

环境修正只改变预制案例允许的结果，不进行实时概率判定。同一个设置始终产生同一个
结果。

## 任务卡

任务卡必须公开：

- 本局实验协议。
- 目标灯光状态。
- 安全电流范围。
- 最高允许温度。
- 当前环境条件。
- 两条与本局答案一致的部分线索。
- 正式实验上限为三次。

线索从案例允许的线索池中选择，例如：

```text
目标样本在干燥状态下不导电。
Alpha 不是低功率电池。
样本 A 遇水后电流会升高。
样本 C 不适合进行耐热测试。
高湿环境下不得使用低耐受样本。
```

任务卡不直接给出正确电池、样本和处理方式。所选线索必须让初始候选组合保持在 4～6
个之间，避免答案过于明显，也避免三次实验内无法推理。

## 回合随机生成

初始版本使用 12 套经过验证的案例，每种协议 4 套。每局按以下顺序初始化：

1. 使用 AI Play seed 或本地随机种子选择一套案例。
2. 随机映射低功率、额定功率和高功率到 Alpha、Beta、Gamma。
3. 从案例允许的材料档案中选择三个，并随机映射到 A、B、C。
4. 选择与案例兼容的环境条件。
5. 计算所有电池、样本和处理方式组合的确定性结果。
6. 验证只有一个组合满足本局全部成功条件。
7. 选择两条不会直接暴露答案的有效线索。
8. 从预设安全锚点中选择电池和金属棒位置。
9. 更新任务卡、标签、状态面板和公开观察。
10. 将实验次数设置为 `0/3`，清除上一局状态。

如果案例无法满足唯一答案、线索范围或三次实验可推理要求，则不得开始回合，应回退到
一套固定的已验证案例并记录开发日志。该错误不得把无效案例或隐藏答案发送给 MCP。

## 空间随机化

- 三块电池从六个近距离候选锚点中选择三个位置。
- 金属棒从三个实验工作台锚点中选择一个位置。
- 任务卡从出生点附近两个明显锚点中选择一个位置。
- 样本、样本选择按钮、处理按钮、电池槽、金属棒槽和运行按钮保持固定。

空间随机化用于促使玩家观察环境，但不得把任务变成长距离找物。所有关键候选应位于实验
区域内，且从出生点不需要经过射击场、危险区或 NPC 区域。

## 玩家流程

### 阶段一：读取与检查

1. 玩家在实验区入口出生。
2. 读取附近任务卡，确认协议、安全范围、环境和部分线索。
3. 查看三个样本标签、三块候选电池和实验状态面板。

### 阶段二：搭建设备

1. 拾取一块候选电池并放入电池槽。
2. 按下 A、B 或 C 的样本选择按钮。
3. 使用实验台按钮选择保持干燥、湿润或加热。
4. 拾取金属棒并放入金属棒槽。
5. 查看状态面板是否显示“设备准备完成”。

### 阶段三：运行、观察与修正

1. 按下“运行实验”。
2. 观察电源、电流、温度、稳定性和灯光结果。
3. 如果失败，根据结果更换电池、样本或处理方式。
4. 再次运行实验，最多三次。

## 正式实验计数

只有同时满足以下准备条件后按下“运行实验”，才消耗一次机会：

- 电池槽中存在一块本局候选电池。
- 已选择样本 A、B 或 C。
- 金属棒已经放入卡槽。
- 实验控制器当前不在运行或复位状态。

缺少任一条件时，面板显示 `setup_incomplete`，不增加实验次数。重复按下正在运行的按钮
也不增加次数。

一次正式实验开始后立即锁定本次电池、样本和处理状态。运行期间移除物品不会改变本次
结果。

## 实验反馈

每次正式实验公开以下结果：

```text
实验：1/3
电源输出：低 / 正常 / 过高
回路电流：无 / 偏低 / 安全 / 过高
稳定性：稳定 / 闪烁 / 中断
样本温度：安全 / 升高 / 危险
灯光：熄灭 / 微亮 / 闪烁 / 稳定
安全状态：通过 / 未通过
```

反馈只描述可测量结果，不显示“电池错误”“样本错误”或正确答案。最近三次结果保留在
面板中，允许玩家比较，不要求玩家完全依赖记忆。

## 典型错误组合

| 组合 | 反馈 | 可推理信息 |
| --- | --- | --- |
| 低功率 + 正确样本 + 正确处理 | 灯微亮、电流偏低、温度安全 | 材料可能正确，但电源不足 |
| 高功率 + 湿态导体 | 电流过高、灯短暂点亮后中断 | 湿态可导电，但电源或电阻不安全 |
| 额定功率 + 绝缘样本 | 电源正常、电流为零、灯熄灭 | 电源可能正确，回路没有导通 |
| 任意电池 + 错误处理 | 电流不稳定或中断 | 应重新判断材料需要的状态 |
| 高功率 + 热敏导体 + 加热 | 温度危险、燃烧警报、回路中断 | 样本不耐热或功率过高 |
| 低功率 + 高电阻导体 + 加热 | 电流偏低、灯闪烁 | 处理方向可能正确，但输出不足 |

危险组合会播放火花、燃烧或熔断效果，消耗一次正式实验机会，然后进入自动复位；不会在
第三次之前单独触发终局。实验样本在该玩法中不对玩家造成持续伤害，避免视觉反馈变成
不可控的死亡条件。

## 失败后的复位

前两次正式实验失败后：

1. 保留本次结果到历史面板。
2. 关闭实验灯并释放电路电力。
3. 清除样本的湿润、燃烧、通电和临时温度状态。
4. 解锁电池槽、样本选择按钮和金属棒槽。
5. 电池和金属棒保持在当前位置，玩家可以主动更换。
6. 将当前处理状态恢复为 `dry`。
7. 面板显示剩余正式实验次数。

复位期间所有运行按钮输入均被忽略，且不消耗次数。

## 成功终局

一次正式实验同时满足以下条件时成功：

- 当前协议要求得到满足。
- 使用本局正确电池性能。
- 使用本局正确材料档案对应的样本。
- 样本处理状态正确。
- 金属棒在连接槽中。
- 电流位于任务卡安全范围。
- 稳定性为 `stable`。
- 温度不超过任务卡阈值。
- 不存在短路或燃烧。
- 实验灯连续稳定点亮 3 秒。

成功终局：

```text
outcome = success
reason = experiment_completed
```

如果第三次实验开始后满足成功条件，必须优先完成成功终局，不能再触发次数耗尽失败。

## 失败终局

第三次正式实验完成后仍未满足成功条件：

```text
outcome = failure
reason = experiment_attempts_exhausted
```

AI Play 还允许独立的请求上限失败：

```text
outcome = failure
reason = max_requests
```

初始建议 MCP `act` 请求硬上限为 150 次。普通玩家和 AI 玩家都受三次正式实验限制；
只有 AI 玩家额外受 MCP 请求上限限制。

## 示例回合

公开任务卡：

```text
协议：防潮测试
目标：湿润样本后，使实验灯稳定点亮 3 秒。
安全电流：2～4 A
最高温度：60 C
环境：高湿
线索：目标样本在干燥状态下不导电。
线索：Alpha 电池不满足本次实验要求。
```

隐藏配置，仅供开发与测试：

```text
Alpha = 低功率
Beta = 高功率
Gamma = 额定功率
A = 热敏导体
B = 干态导体
C = 湿态导体
正确组合 = Gamma + C + wet
```

可能的三次流程：

1. `Beta + C + wet`：电流过高并中断，玩家判断样本可能正确但电池过强。
2. `Gamma + A + wet`：电流不稳定，玩家排除样本 A。
3. `Gamma + C + wet`：灯稳定点亮 3 秒，成功。

### MCP 工具兼容

玩法不得增加新的 MCP 工具，继续使用现有接口：

- `briefing()`：返回白名单公开任务说明和固定参考图。
- `observe()`：返回最新批准的结构化观察和 768x432 JPEG。
- `act(observation_id, actions)`：每批提交 1～3 个现有白名单动作。
- `stop()`：停止 AI 控制并释放全部模拟输入。

所有实验操作必须映射到现有动作，不扩展协议版本 3 的 action schema：

| 游戏操作 | MCP 动作 |
| --- | --- |
| 观察环境 | `look`、`probe_interaction`、`observe` |
| 接近实验台 | `move`、`sprint`、`jump`、`crouch` |
| 读取或关闭任务卡 | `interact`、`close_ui` |
| 拾取/放置电池和金属棒 | `interact` 或 `interact2` |
| 选择样本和处理方式 | `interact` |
| 运行实验或手动复位 | `interact` |
| 等待三秒稳定判定 | `wait` |

`act` 的交互动作必须是当前 observation 中
`interface.available_interactions` 明确公开的 `interact` 或 `interact2`，且改变上下文的
动作必须位于 action batch 最后。单个物体同时公开的交互不得超过两个。

现有 MCP 没有射击或使用 wieldable 的动作，因此发射水/火飞镖不能成为 AI 完成任务的
必需步骤。实验台按钮负责触发现有水/火效果和材料状态。

### 协议与场景注册

- Godot hello 继续发送 `protocol_version = 3` 和
  `scenario_id = "laboratory_experiment"`。
- Python `ai_play.scenarios` 和 Godot `SCENARIO_TERMINAL_RESULTS` 必须同步注册成功、
  三次失败和 `max_requests` 三种终局。
- 场景只允许精确传入 `-- --ai-play` 时连接 `127.0.0.1:8765`。
- 普通启动可以游玩同一任务，但不连接桥、不应用 MCP 请求上限。
- 断连、无效数据、节点销毁、`stop()` 和 Escape 都必须释放模拟输入。

### Laboratory observation DTO

基础 observation 字段保持不变，只增加一个经过 Python 严格验证的可选 `laboratory`
对象。建议固定字段如下：

```text
objective: bounded string
protocol: stable_conduction | moisture_safety | thermal_tolerance
environment: standard | high_humidity | limited_cooling | power_fluctuation
attempts_used: integer 0..3
attempts_limit: integer 3
battery_installed: none | alpha | beta | gamma
selected_sample: none | a | b | c
sample_state: dry | wet | heated
metal_bar_installed: boolean
setup_ready: boolean
experiment_running: boolean
last_power: none | low | normal | high
last_current: none | zero | low | safe | high
last_stability: none | stable | flicker | interrupted
last_temperature: none | safe | elevated | dangerous
last_lamp: none | off | dim | flicker | stable
completed: boolean
failed: boolean
```

任务卡线索仍通过玩家实际打开后的 `interface.visible_object_text` 公开，不能因为
`laboratory` DTO 的存在而提前暴露。DTO 只提供 HUD 和仪表可见的回合状态。

公开 briefing 只包含：

- 任务目标与三次正式实验规则。
- 电池、样本、处理、安装、运行和复位的公开操作说明。
- 实验面板字段的含义。
- 固定的场景参考图和安全规则。

运行时 observation 可以包含：

- 当前协议和任务卡可见文本。
- 当前环境条件。
- 已使用次数和剩余次数。
- 电池槽、金属棒槽和当前样本的可见状态。
- 当前处理状态。
- 最近三次实验的公开测量结果。
- 玩家基础状态、画面和当前可见交互提示。

禁止公开：

- 正确组合。
- Alpha、Beta、Gamma 的隐藏性能映射。
- A、B、C 的隐藏材料档案。
- 未执行组合的结果。
- 案例编号、随机种子或生成器内部候选列表。
- 场景节点路径、内部类名、测试或本文件内容。

## 确定性与可解性

- 回合开始后，所有材料、电池、环境和位置映射保持不变。
- 同一个 seed 必须复现相同案例、映射、线索和空间位置。
- 实验结果由案例规则确定，不使用运行时概率。
- 每套案例必须恰好存在一个成功组合。
- 任务卡出现后，初始可行组合保持在 4～6 个。
- 错误组合的反馈必须与正确组合使用同一套规则计算。
- 自动案例验证测试必须枚举全部 27 个基础组合，并拒绝无解或多解案例。

## 验收重点

- 玩家可以在不读取开发者资料的情况下理解操作方式。
- 所有关键物件都位于实验区并有明确可见标签。
- 准备不完整不会浪费正式实验次数。
- 前两次错误结果提供可用于推理的信息，但不直接泄露答案。
- 第三次正确实验成功优先于次数耗尽失败。
- 第三次错误实验稳定触发 `experiment_attempts_exhausted`。
- 复位会释放所有模拟输入、电力、燃烧和临时状态。
- 普通启动不启用 AI Play；只有精确传入 `-- --ai-play` 才连接本地桥。
- Escape 始终保留为物理紧急停止键。

## 非目标

初始版本不包含：

- 真实电学模拟或连续电路求解器。
- 新的复杂实验室模型或动画资产。
- 玩家自由连接任意导线拓扑。
- 超过三块电池、三个样本或三种处理方式。
- 随机仪表误差、概率性设备故障或不可解释的错误结果。
- 需要离开实验区的大范围探索。
- 多人协作实验。

这些内容会显著扩大实现和测试范围，也会削弱三次实验内基于确定性反馈进行推理的核心
玩法。
