# 游戏脚本：find_key

## 任务定位

`find_key` 是一个简单的办公室找物任务，主要评测 Agent 是否具备主动空间探索、
语义导航和近距离物体搜索能力。

本任务不包含密码、数字组合、多段解谜或开门要求。玩家只需要读取唯一任务卡，根据
任务卡对环境的描述，在办公室中找到并拾取唯一一把钥匙。

本文件是开发者玩法说明，不是运行时模型输入。MCP 只能获得单独维护的公开 briefing，
不得读取或转发本文件中的候选位置、初始化规则和内部实现信息。

## 核心目标

玩家需要：

1. 读取出生点附近的任务卡。
2. 根据任务卡描述判断应该探索的办公区域。
3. 找到场景中唯一的钥匙。
4. 成功拾取钥匙。

成功拾取钥匙后，本局立即成功结束。玩家不需要使用钥匙打开任何门。

## 场景约束

- 场景中只允许存在一个任务卡。
- 场景中只允许存在一把 `Pickup_Key`。
- 钥匙必须使用现有 `pickup_key.tscn` 及其 `PickupComponent`。
- 每次载入 `find_key` 回合时，钥匙从四个候选位置中随机选择一个位置。
- 未被选中的候选位置不得生成钥匙或钥匙替身。
- 办公室中可以保留其他非钥匙 Pickup，但不能出现第二个钥匙物品。
- 钥匙应稳定停留在候选表面上，不能因为刚体物理掉到家具下面或不可达区域。

## 四个钥匙候选位置

每个位置都对应一条任务卡描述。任务卡只显示本局选中的一条，不显示完整候选列表。

### 1. 有笔记本电脑的办公桌

场景语义位置：

- `CEO OFFICE`
- 有笔记本电脑的办公桌桌面

任务卡内容：

```text
寻找办公室钥匙

办公室里只有一把钥匙。
钥匙在有笔记本电脑的办公桌上。

找到并拾取它。
```

主要考察：

- 区分台式电脑与笔记本电脑
- 主动进入独立办公室
- 搜索桌面可拾取物

### 2. 档案室旁边的沙发

场景语义位置：

- `ARCHIVE` 附近
- 靠近档案室的沙发座面

任务卡内容：

```text
寻找办公室钥匙

办公室里只有一把钥匙。
钥匙在档案室旁边的沙发上。

找到并拾取它。
```

主要考察：

- 识别 `ARCHIVE` 文字标识
- 理解“旁边”和“沙发上”
- 到达目标区域后检查非桌面表面

### 3. 会议室的长桌

场景语义位置：

- `MEETING ROOM`
- 会议室长桌桌面

任务卡内容：

```text
寻找办公室钥匙

办公室里只有一把钥匙。
钥匙在会议室的长桌上。

找到并拾取它。
```

主要考察：

- 识别会议室
- 根据长桌和座椅理解房间用途
- 沿较大桌面进行视觉搜索

### 4. 有大电视的茶几

场景语义位置：

- 有大电视和休息家具的公共区域
- 面向大电视的茶几桌面

任务卡内容：

```text
寻找办公室钥匙

办公室里只有一把钥匙。
钥匙在有大电视的茶几上。

找到并拾取它。
```

主要考察：

- 根据“大电视”和“茶几”进行语义定位
- 区分茶几、电视柜和普通办公桌
- 在开放休息区域主动搜索

## 出生点与任务卡规则

可用出生点固定为三个经过验证的安全位置：

1. 办公室入口
2. 大厅
3. `ARCHIVE` 门外

出生点不独立随机。初始化时必须先确定本局钥匙位置，然后计算三个出生点到钥匙位置的
三维世界坐标直线距离，并选择距离最大的出生点。

如果多个出生点的距离完全相同，可以在并列最远点中随机选择一个。不得选择更近的出生点。

任务卡使用与所选出生点配套的任务卡锚点，放在玩家出生位置 1～2 米内。任务卡位置不能
遮挡玩家，也不能要求玩家先探索其他房间才能获得任务。

这一规则保证：

- 每局开始时玩家都能先得到目标描述。
- 玩家不会因为随机出生在钥匙旁边而直接完成。
- 评测重点落在跨空间探索，而不是寻找任务卡。

## 回合初始化顺序

每次载入 `find_key` 回合时按以下顺序初始化：

1. 确认当前选择的场景模式是 `find_key`。
2. 从四个钥匙位置中随机选择一个候选位置。
3. 将唯一 `Pickup_Key` 放置到所选位置，并保证位置稳定且可交互。
4. 计算三个安全出生点到钥匙位置的世界坐标直线距离。
5. 选择距离钥匙最远的出生点。
6. 将玩家移动到该出生点。
7. 将唯一任务卡移动到对应的附近锚点。
8. 把任务卡标题和内容更新为本局钥匙位置对应的描述。
9. 连接钥匙成功拾取信号。
10. 开始本局。

默认运行使用新的随机种子。测试可以提供非零固定种子，以验证位置选择、最远出生点和
任务卡内容具有确定性。随机种子和本局答案属于隐藏状态，不得进入 MCP briefing、
观察结果或日志。

## 交互流程

任务卡允许重复读取。

钥匙使用现有 Pickup 交互：

- 玩家必须靠近并对准钥匙。
- 背包能够接收钥匙时，Pickup 才算成功。
- 背包已满导致拾取失败时，本局不能误判为成功。
- 成功拾取后，钥匙进入玩家背包，世界中的钥匙节点被删除。
- 只有目标钥匙自己的成功 Pickup 信号可以结束本局；拾取其他物品不能成功。

## 终局规则

### 成功

条件：

- 玩家成功拾取本局唯一钥匙。

内部结果：

```text
outcome = success
reason = key_picked_up
```

界面建议：

```text
任务成功
已找到办公室钥匙
```

### 失败

找错区域、拾取其他物品、重复搜索或提前经过钥匙所在房间都不会立即失败。

当前唯一自动失败条件：

```text
outcome = failure
reason = max_requests
```

`find_key` 的场景硬上限是 150 次 MCP `act` 请求。每个到达 Python `act()` 的调用都
计数，包括观察编号过期、动作非法、上下文不允许和已有动作在途等失败请求；
`briefing`、`observe` 和 `stop` 不计数。

第 150 次请求仍先按正常规则执行：如果该请求成功拾取钥匙，以
`success/key_picked_up` 为准；否则触发 `failure/max_requests`，并沿用 AI Play 既有
失败界面和输入释放流程。连接成功附加或重连时，本局请求计数清零。

普通玩家模式不调用 MCP，因此不适用请求次数终局。

## 评测重点

`find_key` 不以复杂解谜为目标，主要观察：

- 是否主动离开出生点探索办公室。
- 是否先读取任务卡并保留目标描述。
- 是否理解台式电脑、笔记本、档案室、沙发、会议长桌、大电视和茶几等环境语义。
- 是否能利用房间文字标识和家具布置进行导航。
- 到达正确区域后是否会调整视角、靠近家具并搜索桌面或座面。
- 搜索错误区域后是否能主动换区域。
- 是否记得已经检查过的空间，减少来回重复。
- 是否能正确使用 Pickup，而不是只看到钥匙就宣布完成。

建议记录：

- 成功率
- 完成所需 MCP 请求数
- 进入错误区域的次数
- 重复访问同一区域的次数
- 从进入正确区域到拾取钥匙的请求数
- 无效交互次数
- 是否达到最大请求上限

## 与 find_contract 的关系

- 两个任务复用同一个 Lobby 场景和通用 AI Play 控制层。
- `find_contract` 继续作为默认场景模式。
- `find_key` 是独立场景模式，不运行合同密码、三段记录或密码盘终局逻辑。
- 两个任务不能在同一回合同时初始化。
- 两个模式可以复用出生点和任务卡锚点，但各自负责自己的任务内容和终局信号。
- `find_contract` 与 `find_key` 的请求硬上限均为 150。
- `AI_PLAY_MAX_ACT_REQUESTS` 只作为全局收紧值；实际请求上限取场景硬上限与该配置中
  较小者，不能用环境变量把场景放宽到超过其硬上限。

建议启动语义：

```text
普通 find_contract：
不提供场景参数

普通 find_key：
--ai-play-scenario=find_key

AI find_contract：
--ai-play

AI find_key：
--ai-play --ai-play-scenario=find_key
```

## 非目标

本任务暂不包含：

- 使用钥匙开门
- 密码输入
- 多把钥匙真假判断
- 钥匙颜色或编号推理
- 多任务卡顺序
- NPC 对话
- 计时失败
- 动态移动钥匙
- 将四个候选位置公开给 Agent

这些内容会引入额外推理或状态管理，削弱本任务对主动空间探索能力的单独测量。
