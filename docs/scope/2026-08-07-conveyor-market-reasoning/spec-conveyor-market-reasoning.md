# Conveyor Profit 市场推理与在线经营脚本

## 目标

把现有五套仅改变固定窗口顺序的 `conveyor_profit` 关卡，替换为五套各十轮的市场经营脚本。
玩家每轮面对三道可完成菜品、当前准确需求倍率和两条关于下一轮的市场信号；玩家需要在当前
利润、下一轮趋势和“每道菜最多成功制作两次”的历史之间做有限规划。

难度不得来自偷看未来后的全局最优答案。通关基准必须是一条只依赖当轮公开信息、下一轮信号
和玩家自己记录的历史制作次数的在线推荐路线。完整十轮动态规划只保留为开发者对照指标。

## 核心规则

- 一局十轮，每轮最多 `MAKE` 一次，窗口时长和 AI 暂停计时规则保持不变。
- 每轮传送带摆放 16 盘食材，并且恰好能完成脚本指定的三道菜。
- 食材按窗口独立到货，不跨轮累计；上一轮使用牛油果不影响下一轮重新出现牛油果。
- 每道菜整局最多成功制作两次。累计次数不显示，玩家必须根据成功收据自行记录。
- 第三次制作、非法组合、成本处罚、窗口锁定、五份托盘上限和 `wait_next_window` 保持不变。
- 每局选择一套市场脚本；五套脚本不放回抽取，五局用完后重置抽取池。
- 基础菜谱、基础售价和食材成本继续公开。

## 菜品类别与动态经济

十道菜归入五个公开类别：

| 类别 | 菜谱 |
| --- | --- |
| `salad` | `garden_salad`、`avocado_salad` |
| `soup` | `carrot_sausage_soup`、`pumpkin_sausage_soup` |
| `burger` | `classic_burger`、`avocado_burger` |
| `omelet` | `broccoli_bacon_omelet`、`corn_bacon_omelet` |
| `sandwich` | `garden_fish_sandwich`、`avocado_fish_sandwich` |

每轮每个类别处于以下四档之一：

| 状态 | 售价倍率 |
| --- | ---: |
| 低迷 | `0.75` |
| 正常 | `1.00` |
| 旺盛 | `1.25` |
| 爆发 | `1.50` |

食材成本不受需求影响。调整后售价统一按
`floor(base_sale_price * multiplier + 0.5)` 取整，调整后净利润等于调整后售价减配方食材成本。
当前五类倍率和当前十道菜的调整后售价必须公开显示；未来准确倍率不得公开。

## 市场信号

- 第 1 至第 9 轮固定给出两条关于下一轮的自然语言信号；第 10 轮不再给信号。
- 每条信号必须明确写出受影响类别以及“可能升高”或“可能降低”，不要求玩家猜隐喻。
- 信号强弱通过人数、范围、距离、持续时间和确定性表达，不直接标记数值强弱。
- 两条信号可以指向不同类别、同类叠加或同类冲突。
- 下一轮开始后公开实际倍率，形成对上一轮推理的反馈。
- briefing 只说明上述通用规则，不包含五套脚本、逐轮信号、候选菜或推荐答案。

## 在线推荐路线与通关目标

“推荐路线”遵循以下信息边界：

1. 只读取当前三道可完成菜的公开盘面、当前准确利润和本轮两条下一轮信号。
2. 只读取此前成功收据，由路线自行维护每道菜已制作 `0..2` 次。
3. 默认偏向当前较高利润；如果当前选择会耗尽最后一次配额，并且下一轮信号明确利好该类别，
   可以选择利润接近的替代菜保留配额。
4. 不读取下下轮及更远的候选菜、倍率、信号或脚本 ID。

每套脚本显式保存并测试一条获批的 `baseline_recipe_id` 序列。基准利润为沿该序列按动态售价
结算的总净利润；通过金额为 `ceil(baseline_profit * 0.90)`。玩家可以找到更好的路线并超过
100% 基准效率。原全局 DP 结果改名为 `omniscient_profit`，只进入开发者测试和本地指标，
不得决定终局、进入 briefing、观察、动作结果或 AWM。

## 食材生成与随机性

每个脚本窗口只保存三个候选菜 ID，不保存一个固定的十六盘数组。生成器执行：

1. 合并三道候选菜各自所需的最大食材计数，得到必需盘面。
2. 使用本局种子随机加入真实食材，直到 16 盘。
3. 仅接受 `attainable_single_dishes()` 结果与三个候选 ID 完全一致的组合；否则重抽干扰食材。
4. 使用独立 RNG 打乱 16 盘出现顺序。
5. 有限次重抽仍失败时，确定性地重复当前已验证安全的必需食材；闭包复验失败则拒绝生成，
   不得返回死局或第四道菜。

相同脚本与种子必须复现相同盘面和顺序；不同种子应至少改变干扰食材数量组合或出现顺序。
候选菜、安全重复策略和生成验证信息都属于隐藏开发数据。

脚本选择采用由种子生成的五项排列和 `draw_index`：`permutation[draw_index % 5]`。人工重开在
同一进程内递增 `draw_index`；可信 AI 启动侧为每个完成的逻辑尝试传入递增索引。基础设施重试
保持同一索引，避免一次逻辑尝试中途更换题目。索引、脚本 ID和排列不得进入模型输入。

## UI 与 AI 公开观察

- HUD 或市场板显示当前五类状态、倍率以及两条完整信号；文本必须无需贴近屏幕即可读取。
- 两页菜谱菜单继续显示基础配方，并根据当前倍率刷新调整后售价和净利润。
- `conveyor` 公开观察新增当前五类倍率和两条信号原文，避免把推理退化为小字号 OCR。
- 当前候选菜不结构化公开；玩家仍需根据 16 盘食材核对可做菜。
- 公开观察不包含脚本 ID、未来倍率、未来信号、推荐路线、基准利润、绝对通过金额、累计次数、
  全知最优或安全后备盘面。
- briefing 公布倍率档位、当前市场与信号的读取方式、90% 在线基准目标和次数规则，不公布脚本。
- AWM 只能保存“记录已做菜、比较当前利润和下一轮信号”这类公开证据支持的工作流。

## 验收标准

- 五套脚本各有十轮、每轮三个唯一候选、五类合法倍率、第 1–9 轮各两条信号、第 10 轮零信号。
- 每条信号明确类别和升降方向；叠加、冲突和规模比较与下一轮实际倍率一致。
- 所有获批推荐路线在逐轮历史下合法，利润依次为 `194/213/184/229/234`，目标依次为
  `175/192/166/207/211`。
- 推荐路线验证只读取当轮数据、下一轮信号和此前计数；终局使用在线基准的 90%，不使用 DP 最优。
- 每个生成窗口恰有 16 盘且恰好支持指定三道菜；多种种子不会产生第四道菜或死局。
- 五局脚本不重复，基础设施重试复用同一题，固定种子与索引可复现。
- 动态售价、实际收入、收据利润、HUD、菜单和开发指标使用同一取整公式。
- AI 观察公开当前倍率和两条信号，但不泄露隐藏脚本、未来、候选、次数或答案。
- 人类点击和 AI 语义动作继续共用同一结算路径，Escape、断线和销毁仍释放模拟输入。

## 范围之外

- 不增加跨轮食材库存、采购、顾客实体、烹饪动画或同轮多次制作。
- 不把线索写成需要猜类别的文字谜语，也不公开下一轮准确倍率。
- 不让真实外部 MCP 验收自动运行；仍需用户另行确认截图、令牌、费用和本地轨迹持久化。
- 不修改其他 AI Play 场景，也不把 `game_script/`、`code_read/`、测试或本 spec 输入运行时模型。
