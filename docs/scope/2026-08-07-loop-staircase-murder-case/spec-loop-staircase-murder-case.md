# 循环楼梯五轮凶案推理

## 目标

把 `loop_staircase_anomaly` 从“跨轮寻找唯一完全不变房间”改造成一场五轮累积证据的
凶案房间推理。玩家在 2F 到 9F 的八个房间中维护逐轮视觉记录；每轮只获得一条新线索，
并把该线索与此前房间状态和已公布线索结合。候选集合按 `8 → 6 → 5 → 3 → 2 → 1`
收缩，第五轮必须把访客、普通物品、垃圾数量和多色状态灯四条历史曲线对齐到同一时间点，
才能选择唯一的凶案楼层。

本任务保留现有 `loop_staircase_anomaly` 场景 ID、2F–9F 的 Up/Down 导航、第五轮 Space
提交、终局原因和 AI First Play 安全边界。改造重点是案件生成、八层房间美术区分、累积
线索 HUD 和调查板，不新增可直接泄露答案的结构化状态。

## 决策

- 最终答案只包含凶案发生楼层，不要求玩家额外提交凶手身份或完整路线。
- 八层固定分成四组功能：2F–3F 为休息区，4F–5F 为档案室，6F–7F 为办公室，8F–9F
  为会议室。功能与楼层的对应关系不随回合改变。
- 同组两层共享可识别的功能语言，但拥有不同的布局、家具组合、颜色和稳定地标。两个办公室、
  两个档案室等不能是复制房间，也不能仅靠楼层牌区分。
- 案件沿用 `round_seed` 的确定性随机回合。每个种子生成受害者姓名、凶案楼层、访客集合、
  普通物品变化、垃圾曲线、灯光曲线和最终时间对齐关系；相同非零种子必须生成相同案件。
- 每轮只公布一条本轮线索，未来轮次线索不可提前出现在场景、briefing、结构化观察或调查板。
  旧线索累计保留，并以“第一轮线索”“第二轮线索”等标签显示；当前新增内容始终标为
  “本轮线索”。进入下一轮后，上一条“本轮线索”转成对应的固定轮次标签。
- 中间轮次不要求提交候选集合，也不验证玩家手动标记是否正确。只有第五轮最终选择判定胜负，
  防止通过反复试选获得答案反馈。
- 第 1–4 轮不出现凶器、血迹、尸体、秘密文件、明显异物或其他天然带有犯罪含义的视觉证据。
  杯子、书本、台灯、电脑、沙发、电视、纸箱和垃圾等变化都必须能解释为普通办公活动，且
  错误候选拥有同等级的视觉显著性。
- 最终线索不新增一个指向答案的房间特征，而是说明如何把前四轮已经观察到的证据对齐。
  正确房间不是变化最多或最整洁的房间，而是唯一满足完整时间关系的房间。
- 隐藏答案、内部候选集合、每轮消除列表、房间状态表、随机种子和正确时间点只供可信 Godot
  逻辑及测试使用，不能进入公开 briefing、观察、动作结果、轨迹结果或玩家提示。

## 架构

### 案件模型

`LoopStaircaseManager` 持有一份可信的回合案件模型。模型为每层保存不可变主题和稳定地标，
并为五轮保存可见房间状态。案件模型另外保存仅内部可见的正确候选集合：第一轮 6 层、第二轮
5 层、第三轮 3 层、第四轮 2 层、第五轮 1 层。

生成器先选择最终楼层，再反向生成每轮证据，保证正确楼层始终保留、每轮只按目标数量淘汰
错误楼层，并保证第五轮只有一个时间点能够同时满足全部约束。生成结束后必须执行内部一致性
校验；无法满足约束的生成结果不得进入可玩状态。

### 房间主题

每层房间由稳定主题层和案件证据层组成：

- 稳定主题层决定墙面、主色、固定家具、主要布局和不会参与案件变化的辨识地标。
- 案件证据层只控制访客记录、普通可变物品、地面垃圾和多色状态灯。
- 受控证据节点应使用小型组件或数据驱动槽位，不得通过重建整个房间制造无关变化。

四组功能至少具有以下辨识边界：

- 休息区包含休闲座椅和茶几，但两层使用不同座椅组合、照明和辅助设施。
- 档案室包含档案存储和查阅区域，但两层分别偏纸质存储与数字工作台。
- 办公室包含办公桌和电脑，但两层分别偏独立管理办公室与开放工位。
- 会议室包含会议桌和展示设备，但两层使用不同桌型、座位数量和墙面设备。

### 调查板

调查板按“楼层 × 轮次”保存玩家实际访问时的房间缩略快照。快照不叠加自动检测框、差异文本、
物品计数或正确性标记。玩家可以手动切换某层的候选标记；该标记只服务于玩家记录，不影响
案件逻辑，也不进入终局判定。

人类玩家使用 Tab 打开或关闭调查板。调查板打开时，Up/Down 选择楼层行，Space 切换该行的
候选标记；调查板关闭时，Up/Down 继续切换楼层，Space 只在第五轮提交当前楼层。AI Play
为本场景扩展 `press_key` 白名单以接受 `tab`，并复用 Up/Down/Space；其他场景仍拒绝这些
场景专用按键。

每轮必须捕获 2F–9F 的八张快照后才能从 9F 进入下一轮。缺少快照时，场景只显示尚未观察的
楼层，不提供候选正确性反馈。

### 公开信息

公开 briefing 只说明玩家需要逐层观察、使用调查板维护历史、每轮读取一条累积线索并在第五轮
选择楼层；不得列出未来五条具体线索或任何生成规则。结构化 `staircase` 观察继续只公开当前
楼层、当前轮次、总轮次、最终提交是否解锁和终局布尔值。房间细节、缩略图和线索文字只通过
玩家可见画面提供。

## 流程

### 开局与第一轮：访客姓名

开局生成一个受害者姓名。本轮线索只要求寻找访客记录中出现该姓名的房间。每个房间在与其
功能一致、位置稳定且可从第一人称画面检查的位置展示访客记录；记录中可以出现多个姓名作为
干扰。八层中恰有六层包含受害者姓名，内部候选集合从 8 层缩小到 6 层。

第一轮的访客记录只显示姓名，访问轮次字段保持遮挡。第五轮开始时，同一批记录解除访问轮次
字段的遮挡，并由第五轮本轮线索说明如何将它与既有证据对齐；玩家不能在第一轮提前完成最终
推理。

### 第二轮：普通物品变化

第二轮线索要求玩家比较第一、二轮快照，寻找指定类别的普通环境变化。变化可使用新增、消失、
替换和同类物体数量变化，例如新增杯子或纸箱、笔记本换成台式电脑、单人沙发换成双人沙发、
大电视消失。

六个第一轮候选中恰有五个符合本轮关系。错误房间仍可出现普通视觉变化，但不能满足本轮线索
定义的完整条件。任何变化都不得通过“与房间风格明显不符”、唯一材质、发光描边、悬浮身份
标签或犯罪语义获得额外显著性。

### 第三轮：垃圾清理曲线

第三轮线索用自然语言公布清洁员习惯：“他每次经过房间，只会顺手带走一件垃圾。”线索不直接
写成数学表达式。

第二轮的五个候选中：

- 一层从基准轮开始没有地面垃圾，因无法形成清理轨迹而排除。
- 一层垃圾逐轮减少，但至少一次减少数量不是一件。
- 三层在可比较的每次轮次转换中都严格减少一件垃圾。

其他楼层也可以没有垃圾或拥有干扰曲线。生成器应让正确和错误候选在第三轮具有相同的当前
垃圾数量案例，确保只看本轮画面无法判断，必须比较历史快照。

### 第四轮：双色 ABAB 状态灯

第四轮线索公布一种与案件秘密相关的状态灯规律：目标房间在前四轮只出现两种颜色，并严格按
`A → B → A → B` 交替。线索以可理解的剧情语言描述双色交替，不使用“偶数次变化”这一有
歧义说法。

第三轮的三个候选中恰有两个满足 ABAB。错误候选使用同等级干扰序列，例如 `A → B → A → C`
或 `A → B → B → A`。不同候选可以使用不同颜色对；具体颜色本身不代表答案。当前颜色相同的
正确和错误候选必须存在，以避免第四轮单帧判断。

### 第五轮：时间点对齐

第五轮线索公布受害者访问时间以及一条组合关系，要求玩家寻找访客、普通物品、垃圾和灯光
证据在同一轮汇合的房间。第四轮的两个候选都分别满足前四条独立线索；只有正确房间存在一个
时间点，同时满足：

- 受害者在该时间点进入或停留于该房间。
- 本轮关注的普通物品已经从同功能的配对房间转入，并且来源房间的减少与目标房间的增加能由
  此前快照共同证明。
- 垃圾数量处于清洁曲线所定义的对应阶段。
- 多色状态灯处于 ABAB 周期中由最终线索指定的相位。

最终线索只描述这四者的关系，不出现楼层号、功能组名称、物体实例名、颜色常量或候选数量。
错误候选至少在两个不同维度上仍显得合理，但四项不能在同一时间点同时成立。玩家关闭调查板、
用 Up/Down 显示推断楼层并按 Space 后，正确产生 `success/correct_floor_selected`，错误产生
`failure/wrong_floor_selected`。

## 验收标准

- 2F–9F 固定形成四组成对功能房间；同组两层从完整房间截图中可稳定区分，且不会因案件证据
  变化丢失其主题身份。
- 至少对 300 个固定种子验证案件确定性、唯一解和严格的 `8 → 6 → 5 → 3 → 2 → 1`
  内部候选曲线；任一中间轮次都不能单独唯一确定答案。
- 每轮只新增一条线索。HUD 和调查板按已完成轮次列出旧线索，并只把当前新增线索标为
  “本轮线索”；未来线索的文本和规则均不可见。
- 第一轮恰有六层访客记录含受害者姓名；房间中的记录可从正常第一人称观察发现，不依赖
  结构化观察字段。
- 第二轮恰有五个累计候选；所有案件物品变化使用普通环境资产，答案房间不因资产独特性、
  犯罪语义或视觉强调而比错误候选更显眼。
- 第三轮的五个候选包含一个零垃圾房间、一个非严格递减房间和三个严格每轮减少一件的房间；
  至少一组正确/错误房间在当前轮垃圾数量相同。
- 第四轮的三个候选包含两个严格 ABAB 序列和一个非 ABAB 序列；至少一组正确/错误房间当前
  灯色相同。
- 第五轮的两个候选都满足前四轮的独立规则，只有正确楼层能在同一个时间点满足四类证据；
  删除任意一类证据后不得仍由最终关系唯一推出答案。
- 调查板为每层每轮保存可见缩略快照，允许玩家手动标记候选，但不自动显示差异、计数、内部
  候选或标记正确性。中间标记错误不会触发成功或失败。
- 未观察完整八层时不能推进轮次；反馈只指出缺少观察的楼层，不提示哪些楼层是正确候选。
- 人类键盘和 AI `press_key` 都能打开/关闭调查板、选择行和标记候选；`tab` 只对
  `loop_staircase_anomaly` 有效，其他场景继续失败关闭。
- 公开 briefing、结构化观察、动作结果和轨迹结果不包含未来线索、房间状态表、缩略图数据、
  隐藏候选、时间对齐答案、种子或其他内部案件事实。
- Escape 继续作为物理紧急停止键；断连、无效动作、节点销毁和终局继续释放所有模拟输入。
- `loop_staircase_anomaly` 仍使用 160 次 act 请求硬上限和既有成功、错误选择、请求上限终局。
- 普通游玩不需要 `--ai-play`；AI 游玩仍需显式 `-- --ai-play --ai-play-scenario=loop_staircase_anomaly`。

### 测试

- 扩展 manager 单元测试，覆盖种子确定性、四组主题、每轮状态、候选数量、零垃圾排除、严格
  `-1` 垃圾曲线、ABAB 与干扰序列、第五轮四证据时间对齐、唯一终局和结束后输入冻结。
- 扩展 Godot 场景测试，覆盖八层视觉主题、访客记录位置、普通物品槽位、垃圾和状态灯可见性、
  累积线索 HUD、调查板快照/手动标记、未完整观察时的轮次阻止和最终提交。
- 扩展 Python 与 GDScript 动作验证测试，覆盖本场景 `tab`、调查板打开时 Up/Down/Space 的
  语义，以及其他场景对场景专用按键的拒绝。
- 扩展 briefing、观察 schema 和桥测试，证明新玩法说明可用但不提前包含具体五轮线索或隐藏
  案件状态，现有协议版本和终局白名单不回归。
- 运行 `tests/check_loop_staircase.sh`、相关 Godot 包装测试、`ai_play` Python 完整测试套件和
  受影响的仓库 Python 测试，最后运行 `git diff --check`。
- 自动化测试不得启动真实外部 MCP 客户端。真实黑盒验收仍须用户另行确认截图、令牌、费用和
  本地轨迹持久化影响。

## 范围之外

- 提交凶手身份、完整作案路线或多项答案。
- 中间轮次候选验证、自动差异检测、自动物品计数、自动证据解释或提示正确候选。
- 写实血腥表现、尸体、跳吓、追逐、战斗、NPC 表演或可交互凶器。
- 新增公网服务、外部模型调用、API Key、真实客户端自动验收或把开发者规格作为运行时输入。
- 修改其他 AI Play 场景的目标、动作或公开观察字段。
