# Conveyor Profit 十分钟利润效率策略设计

## 目标

把游戏从单一 `$100` 净利润目标改成十个一分钟策略窗口。每个窗口提供一批只能组成
1–2 种候选菜的有限食材，玩家最多成功制作一道菜。系统以每个窗口能做出的最高单份
净利润为基准，要求整局实际净利润达到理论最高总利润的 80%。

该规则要求 AI 观察当前食材、读取公开配方、比较候选菜利润并选择更贵的一道，而不是
只要做出任意合法菜或等待更多制作额度。AI 通过场景专用的语义动作返回英文食材名，
游戏在当前画面内的同名食材中随机选择一个；AI 不模拟移动、瞄准或鼠标点击。

## 已确认规则

- 整局固定 10 分钟，由 10 个连续的 60 秒窗口组成。
- 每个窗口刷新一批有限食材；上一窗口未使用的食材和托盘内容在切换时过期。
- 每批食材能完整组成 1–2 种候选菜，不出现第三种意外候选菜。
- 每个窗口最多成功制作一道合法菜。
- 合法菜制作后立即锁定该窗口的选择、撤销和制作输入，直到下一窗口开始。
- 非法组合会清空托盘、消耗选中食材、收入为零并降低净利润，但不锁定窗口；如果剩余
  食材仍足够，玩家可以在当前窗口继续尝试。
- 原 `$100` 净利润通关目标取消。
- 最终通关条件为：

```text
实际净利润 >= ceil(十个窗口理论最高单份净利润之和 × 0.8)
```

- 未制作菜品的窗口贡献实际利润为零，但该窗口的理论最高利润仍进入通关基准。
- 实际净利润包含所有非法组合造成的负利润。

## 窗口供应

新增确定性的窗口供应生成器。输入显式 seed 和窗口数量，输出十个窗口的公开食材 ID
数组以及仅供内部结算使用的最高单份利润。

每个窗口的生成流程：

1. 从六种公开配方中选择一到两个候选配方。
2. 合并构成候选所需的食材，并允许加入不会形成额外配方的干扰食材。
3. 使用 `RecipeCatalog` 枚举该批食材可形成的所有单份精确配方。
4. 只接受候选种类数为 1 或 2 的批次。
5. 记录这些候选中最高的单份净利润，洗牌后只把食材顺序交给场景。

同一个 seed 必须生成相同的十个窗口。不同 seed 应产生不同候选组合和顺序。运行时不得
向玩家或 AI 公开候选列表、窗口最高利润、未来窗口食材、理论最高总利润或最优菜名。

## 组件边界

### `ProfitSession`

继续作为收入、成本和实际净利润的唯一写入者。删除 `$100` 目标和基于金额的成功终局；
保留配方结算、非法组合成本、托盘和终局冻结能力。

### `ProfitWindowSession`

负责：

- 当前窗口索引、窗口剩余时间和总剩余时间。
- 当前窗口是否已经成功出餐。
- 十个窗口的隐藏最高利润总和与 80% 整数阈值。
- 窗口切换、整局结束和最终 `success/failure`。

它接收显式 `advance_time(delta_seconds)`，便于测试直接推进时间而无需真实等待。任何制作
动作前先结算已经经过的时间；恰好落在窗口边界的动作属于新窗口。

### `ConveyorGameplay`

负责将当前窗口供应填入 16 个循环槽位、在切换时清空托盘和旧食材、更新 HUD，并把
MAKE 结果通知 `ProfitWindowSession`。合法出餐后禁用当前窗口的食材、UNDO 和 MAKE；
下一个窗口开始时重新启用。

人类鼠标点击和 AI 语义动作必须汇入相同的选择、撤销和制作入口，不得维护两套托盘或
经济规则。

### AI Play 场景动作

仅当 `--ai-play-scenario=conveyor_profit` 激活时，现有 MCP `act` 接受：

```json
{"type": "select_ingredient", "ingredient": "tomato"}
{"type": "undo"}
{"type": "make"}
```

`select_ingredient` 只接受 `RecipeCatalog.INGREDIENT_IDS` 中的固定英文 ID。Godot 从当前
窗口内尚未消耗、可选择、正在渲染、处于相机视锥且投影落在游戏画面内的同名食材中，
使用本局 seed 的随机源选择一个。传送带场景不做逐物体遮挡射线检测。其他 AI Play
场景必须拒绝这三种专用动作。

这些动作沿用 `act` 的 `observation_id` 新鲜度校验、每批 1–3 个动作、轨迹记录、协议错误
处理和断连安全退出。动作不接受屏幕坐标、节点路径或运行时对象 ID。

## 状态流

```text
窗口开始
  -> 清空旧托盘和旧供应
  -> 放入当前窗口食材
  -> 允许选择和 MAKE
  -> 非法 MAKE：扣成本，窗口继续
  -> 合法 MAKE：记一份实际利润，锁定窗口
  -> 60 秒结束：进入下一窗口
  -> 第 10 个窗口结束：计算 80% 阈值并终局冻结
```

如果窗口食材由于非法制作已无法形成合法菜，窗口不会提前结束；玩家等待本分钟结束。

## HUD 与公开状态

运行中显示：

```text
TOTAL TIME  09:42
WINDOW  1 / 10  ·  00:42
DISH  0 / 1
NET PROFIT  $0
```

合法出餐后 `DISH` 变成 `1 / 1`，状态行提示等待下一窗口。非法组合显示本次损失和当前
负利润。窗口切换显示新窗口编号。

整局结束时额外显示：

```text
EFFICIENCY  84%  ·  SUCCESS
```

运行中不显示理论最高总利润、80% 的绝对金额门槛或单窗口最优答案。最终效率只在终局
后公开，计算为 `actual_profit / theoretical_best_total`，最低显示可为负数。

## MCP 与安全边界

`conveyor_profit` 白名单 MCP 场景的 `observe` 只提供截图以及玩家在 HUD 和菜单上能看到的
时间、窗口、本窗口出餐状态、实际净利润和托盘。它不返回结构化食材清单；AI 必须从
截图识别当前食材。不得公开：

- 当前窗口候选菜列表或最高利润。
- 理论最高总利润、绝对通关金额或未来窗口内容。
- 生成 seed、隐藏见证、最优动作或内部节点路径。

`act` 的公开结果只说明动作类型、请求的英文食材 ID 和结果状态，不返回被选节点、位置、
隐藏库存或最优策略。结果状态包括：

- `selected`：成功选择一个同名食材。
- `invalid_ingredient`：英文食材 ID 不在白名单内。
- `ingredient_not_available`：当前画面内没有可选的同名食材。
- `window_locked`：本窗口已合法出餐。
- `game_finished`：十分钟整局已经结束。
- `tray_empty`：空托盘执行 `undo` 或 `make`。

失败动作不扣钱、不替换为其他食材，也不改变托盘；游戏时间继续正常流逝。

## 边界行为

- 空托盘 MAKE：无变化，不锁窗口。
- 非法 MAKE：扣成本、清托盘，不锁窗口。
- 合法 MAKE：结算一次并锁窗口；重复 MAKE 无变化。
- 窗口到期时托盘有食材：直接过期，不扣成本，因为成本只在 MAKE 时产生。
- 最后一个窗口边界到达：先结束整局，再拒绝任何新动作。
- 大 `delta` 跨越多个窗口：按顺序跳过对应窗口，载入最终落点窗口；越过 600 秒则直接
  终局。
- 终局后：冻结经济、选择、UNDO 和 MAKE。

## 测试与验收

- GDScript 单元测试覆盖窗口供应确定性、每批只有 1–2 种候选菜、隐藏最高利润正确。
- 窗口会话测试覆盖 60 秒边界、每窗口一道限制、大 `delta`、10 分钟结束和 80% 取整。
- 经济测试覆盖非法组合产生负利润且不锁窗口。
- 场景测试覆盖窗口切换清空托盘与食材、HUD 四项公开字段、合法出餐锁定和下一窗口恢复。
- 协议测试覆盖只有 `conveyor_profit` 接受三个专用动作、英文 ID 白名单、陈旧观察拒绝和
  公开错误结果。
- Godot 集成测试覆盖只从当前画面内同名食材选择、固定 seed 可复现，以及 AI 与人类入口
  产生完全相同的托盘和利润状态。
- 观察测试确认 MCP 不公开结构化食材清单、隐藏最优值、未来供应或内部对象标识。
- 完整回归继续覆盖配方、供应、闭合传送带、双语贴纸和 3D 点击入口。
- 人工验证可使用缩短的测试配置观察窗口切换；正式默认仍为 10 × 60 秒。
- 不运行真实外部 MCP 客户端验收，除非用户再次确认截图、token、费用和日志持久化影响。

## 范围之外

- 不加入顾客、订单队列、购买、升级或长期存档。
- 不按“最优选择次数”计分；只比较最终实际净利润和理论最高总利润的 80%。
- 不允许在一分钟内制作第二道合法菜。
- 不为 AI 模拟移动、转向、准星或鼠标点击。
- 不改变其他 AI Play 场景的控制动作或公开观察。
