# Conveyor Profit 3D Minigame Design

> 由 brainstorming 与 scope 流程于 2026-07-31 生成。

## 目标

在现有 Cogito Lobby 中新增一个可由人类和 MCP 黑盒 AI 以相同规则游玩的 3D
经营小游戏。有限食材沿 U 型闭合回转带循环；玩家观察公开菜单和食材成本，点击食材
组成菜品并自动售出。每份菜品按售价减去食材成本计算净利润，累计净利润达到 100 元
即通关。每局食材有限且顺序随机，但生成器保证至少存在一组可实现 120 元净利润的组合。

首个交付是可运行、可观察的场景垂直切片：U 型回转带、八种食材、料理托盘、菜单板、
制作/撤销按钮和利润显示；随后在同一设计边界内完成经济规则与 MCP 白名单场景。

## 已确认决策

- 场景是第一人称 3D 小游戏，放在现有 `COGITO_3_Lobby` 的白名单玩法体系中。
- 传送带使用 `Path3D`、`PathFollow3D` 和固定槽位，不用刚体互相推动。
- 回转带闭合循环；错过的食材会再次经过，不以反应速度作为主要难度。
- 玩家以屏幕准星点击食材，食材自动进入料理托盘，不要求物理搬运。
- 制作合法菜品后自动售出；无需送到收银台或等待顾客。
- 目标按净利润计算，而非营业额：`净利润 = 收入 - 已消耗食材成本`。
- 非法组合被消耗、没有收入，因此会产生负利润。
- 人类与 AI 使用相同命中和选择入口；AI 不获得按食材名称直选的语义动作。
- 玩法开发者文档放在 `game_script/conveyor_profit.md`；运行时 GDScript 放在
  `conveyor_profit/scripts/`。`game_script/` 绝不进入模型输入。
- 食材美术采用 Kenney Food Kit 的 CC0 低多边形资源，厨房环境复用仓库已有 Kenney
  家具。资源落库前保留来源与许可证说明。

## 场景布局

玩家站在 U 型回转带开口中央。传送带包围玩家前方和左右视野，菜单板、料理托盘和利润
显示布置在正前方操作区，保证玩家只需小幅移动和转身即可完成整局。

```text
┌──────────────────────── 房间 ────────────────────────┐
│   ┌────────────── U 型闭合回转带 ──────────────┐    │
│   │  食材 → 食材 → 食材 → 食材 → 食材        │    │
│   │  ↑                                  ↓      │    │
│   │  ← 食材 ← 食材 ← 食材 ← 食材 ← 食材      │    │
│   └───────┐                           ┌────────┘    │
│           │          玩家             │             │
│           │           ●               │             │
│           └───────────────────────────┘             │
│   [菜单与售价]  [料理托盘/制作/撤销]  [利润 0/100]  │
└──────────────────────────────────────────────────────┘
```

## 领域模型

### 食材

食材定义是只读 Resource，包含稳定 ID、公开名称、成本和场景资源。每个运行时食材实例
有唯一实例 ID 和 `available/selected/consumed` 状态。首版使用八种食材：

| ID | 名称 | 成本 |
| --- | --- | ---: |
| `lettuce` | 生菜 | 1 |
| `tomato` | 番茄 | 1 |
| `bread` | 面包 | 2 |
| `egg` | 鸡蛋 | 2 |
| `mushroom` | 蘑菇 | 2 |
| `cheese` | 奶酪 | 3 |
| `fish` | 鱼 | 4 |
| `meat` | 肉 | 5 |

### 配方

配方按食材 ID 的多重集合精确匹配，不考虑选择顺序。

| 食物 | 配方 | 售价 | 单份利润 |
| --- | --- | ---: | ---: |
| 沙拉 | 生菜、番茄、蘑菇 | 7 | 3 |
| 鸡蛋吐司 | 面包、鸡蛋 | 8 | 4 |
| 奶酪吐司 | 面包、奶酪 | 10 | 5 |
| 汉堡 | 面包、肉、生菜、番茄 | 15 | 6 |
| 鱼肉三明治 | 面包、鱼、生菜 | 14 | 7 |
| 蘑菇蛋卷 | 鸡蛋、奶酪、蘑菇 | 14 | 7 |

### 供应生成

生成器使用显式种子选择若干有效配方作为一组可行见证，直到见证利润不低于 120；随后
把所需食材实例拆散并洗牌。生成器只向运行时返回食材序列，不公开见证配方、最大利润或
最优解。测试可用同一种子重放批次。

## 组件边界

- `ConveyorController`：维护闭合轨道、槽位间距、速度和食材实例加入/移除；不处理经济。
- `IngredientInteractable`：处理屏幕命中，向会话管理器提交唯一食材实例 ID。
- `TrayController`：维护有序选择列表、撤销最后选择和托盘视觉，不计算配方价格。
- `RecipeCatalog`：按食材多重集合查找精确配方。
- `ProfitSession`：拥有库存、成本、收入、利润和终局判定，是经济状态唯一写入者。
- `SupplyGenerator`：从配方目录生成确定性、有限且保证可解的食材批次。
- `ConveyorProfitMonitor`：把公开终局映射到 AI Play controller，不泄露求解器状态。
- `ConveyorProfitObserver`：只补充玩家在 HUD 上可见的利润、托盘与剩余食材摘要。

所有点击最终调用同一个 `IngredientInteractable.select()`。人类由准星交互触发；MCP 使用
归一化屏幕坐标进行一次原子命中与点击，避免移动目标在 `probe` 与 `interact` 两次请求间
离开准星。动作只作用于当时屏幕上实际命中的公开交互物，不能按名称选择隐藏食材。

## 运行流程

1. 场景按种子生成有限食材批次并均匀放入闭合轨道。
2. 玩家查看菜单、成本和售价，点击回转带上的可见食材。
3. 选中食材从轨道移到托盘；撤销将最后一项退回可用库存并重新入轨。
4. 玩家按制作按钮。
5. `RecipeCatalog` 精确匹配配方；`ProfitSession` 总是扣除所选食材成本，合法配方再增加
   售价，并清空托盘。
6. 净利润达到 100 时成功；如果剩余可用食材和托盘无法再让利润达到 100，则失败。

## MCP 与安全边界

新增白名单场景 ID `conveyor_profit`，继续使用 `briefing`、`observe`、`act`。briefing
只公开目标、成本、配方、售价和操作规则。observe 可公开截图、当前利润、托盘食材、
剩余食材数量和当前可见交互提示。act 支持既有移动/观察动作和受边界校验的屏幕坐标点击。

不得公开未来食材顺序、生成种子、可行见证、最大可得利润、最优选择、节点路径、源码或
`game_script/` 内容。MCP 服务仍只绑定 `127.0.0.1`；断连、无效数据、API 失败和节点销毁
必须释放所有模拟输入，且无效动作不得改变经济状态。

终局结果为：

- `success/profit_target_reached`
- `failure/profit_target_unreachable`
- `failure/max_requests`

## 失败处理

- 点击空白或非食材：返回 `not_found`，不改变状态。
- 重复或过期实例 ID：拒绝选择，不改变状态。
- 空托盘撤销：返回无变化结果。
- 非法组合：消耗托盘食材、收入为零、成本照常计入。
- 资源、轨道或关键节点配置缺失：拒绝启动该局并释放 AI 输入。
- 终局后：冻结经济状态，拒绝后续选择和制作。

## 验收标准

- U 型闭合回转带在 Lobby 中可见，食材保持稳定间距并持续循环。
- 八种食材可被准星点击、自动进入托盘并可撤销。
- 菜单板显示完整配方、成本、售价；HUD 显示托盘和净利润进度。
- 合法、非法配方按上述规则结算，净利润达到 100 时成功。
- 任意生成批次都有一组至少 120 元净利润的可行组合，且不向玩家公开该组合。
- 人类和 MCP AI 经过同一个食材命中与选择入口。
- `conveyor_profit` 只有显式 `-- --ai-play --ai-play-scenario=conveyor_profit` 才启用 AI。
- Escape 仍是物理紧急停止键；异常路径释放模拟输入。

### 测试

- GDScript 单元测试覆盖配方多重集合匹配、经济结算、撤销和终局冻结。
- 生成器属性测试覆盖多个固定种子，验证有限性、确定性和至少 120 元可行利润。
- 场景测试覆盖闭合循环、槽位间距、点击命中和 HUD 公开状态。
- Python 测试覆盖 briefing 白名单、动作 schema、终局白名单和敏感字段过滤。
- MCP 桥接测试覆盖过期 observation、越界坐标、断连和输入释放。
- 最后运行相关 Godot 测试、受影响 Python 套件及 `git diff --check`。
- 真实外部 Codex 验收只在用户再次确认截图、token、费用和日志持久化后执行。

## 范围之外

- 顾客排队、点单、情绪和送餐。
- 购买食材、库存补货、升级和长期存档。
- 物理传送带碰撞、食材掉落和堆叠。
- 烹饪时长、火候、切菜和厨具模拟。
- 联机、多关卡和完整商业经营系统。
